# Audit initial - 5 aout 2026

## Etat constate

- Projet actif : `01_PROJET_ACTIF/notalix`.
- Sauvegarde complete creee avant reorganisation : `90_SAUVEGARDES/notalix_avant_reorganisation_2026-08-05`.
- Copie controlee : 2 123 fichiers dans la source et dans la sauvegarde.
- Application statique composee de HTML, CSS et JavaScript, sans installation necessaire pour l'utilisateur.
- Neuf dossiers fonctionnels principaux, plus les outils de generation.
- Environ 520 fichiers audio MP3 et 283 partitions MusicXML.

## Points positifs

- Les grandes activites pedagogiques sont deja separees par dossier.
- Les bibliotheques tierces sont generalement isolees dans des dossiers `vendor/`.
- Les outils de preparation des partitions et de validation des sons sont regroupes dans `tools/`.

## Points de vigilance

- Le README initial ne decrivait pas le projet.
- Les conventions varient selon les modules (`sounds/`, `assets/sounds/`, `Images/`, fichiers par instrument).
- Des banques de sons et des copies de VexFlow sont dupliquees entre plusieurs modules.
- Les styles globaux, le theme et certains styles locaux sont melanges.
- Le depot de versions est present, mais l'outil Git n'est pas installe ou accessible sur cette Surface.
- Aucun lanceur de tests global n'a ete detecte ; les controles doivent donc inclure des ouvertures de pages et une verification des liens locaux.

## Decision pour cette etape

Ne deplacer aucun fichier actif. Ajouter d'abord une documentation fiable et une structure commune vide, puis migrer un seul type de ressource a la fois lors des prochaines etapes. Cette decision protege les chemins relatifs et les comportements pedagogiques.
